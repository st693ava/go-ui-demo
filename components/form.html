Construir formulários com validação nativa e form-inputs FACE — sem biblioteca de forms.

<script>
  document.getElementById('profile')
    .addEventListener('submit', (e) => {
      e.preventDefault()
      // checkValidity()/reportValidity() já correu nativamente;
      // chega aqui só com dados válidos.
      const data = Object.fromEntries(new FormData(e.target))
      console.log(data) // { username: 'goncalo' }
    })
</script>

Não há um componente <go-form>: usas o <form> nativo. Importa o registo uma vez no teu entry-point — regista todos os Custom Elements form-associated (<go-input>, <go-checkbox>, etc.): 

// main.ts / app.js
import '@st693ava/go-ui'
import '@st693ava/go-ui/style.css'

Uso

Os formulários são complicados — uma das coisas mais comuns que constróis numa aplicação web e, ao mesmo tempo, das mais complexas. Um formulário bem desenhado é semanticamente correto, fácil de navegar por teclado, acessível com atributos ARIA e rótulos corretos, e suporta validação no cliente e no servidor.

Ao contrário do shadcn-vue — que usa vee-validate + zod — o go-ui não traz nenhuma biblioteca de forms. Cada input go-* é um Form-Associated Custom Element (FACE): regista-se no <form> nativo pelo seu name, participa em FormData, e expõe validação de constraints via required, minlength, maxlength, pattern, min, max, step, type="email", etc. O navegador trata de checkValidity(), reportValidity() e do bloqueio do submit — sem JS de ligação, sem schema, sem hooks.

Anatomia

Compõe um <form> nativo, opcionalmente com <go-field> para rótulo, descrição e mensagem de erro, e qualquer input go-* FACE no interior. 

<form>
  <go-field
    label="Rótulo"
    for="campo"
    description="Texto de ajuda."
    error="Mensagem de erro."
  >
    <!-- qualquer input go-* FACE ou um input nativo -->
    <go-input id="campo" name="campo" required></go-input>
  </go-field>
  <go-button type="submit">Submeter</go-button>
</form>

Exemplos

Input go-* (FACE)

Os inputs go-* integram-se no <form> nativo pelo name. Com required e type="email", o navegador valida e bloqueia o submit até os dados estarem corretos.

Submeter 
{}
<form>
  <go-field label="Nome de utilizador" for="username"
    description="Este é o teu nome público.">
    <go-input id="username" name="username" required></go-input>
  </go-field>
  <go-field label="E-mail" for="email">
    <go-input id="email" name="email" type="email" required></go-input>
  </go-field>
  <go-button type="submit">Submeter</go-button>
</form>

Input nativo

Não precisas de componentes go-* para participar num <form> com validação — um <input> nativo funciona exatamente da mesma forma. Os inputs go-* são FACE para serem intermutáveis com os elementos nativos.

Submeter 
{}
<form>
  <go-field label="Nome de utilizador" for="username"
    description="Este é o teu nome público.">
    <input id="username" name="username" required minlength="3" />
  </go-field>
  <go-button type="submit">Submeter</go-button>
</form>

Checkbox, radio e select

Vários form-inputs FACE num único <form>. Cada um entra no FormData pelo seu name; required bloqueia o submit até haver escolha.

Aceito os termos e condições Submeter 
{}
<form>
  <go-field label="País" for="country">
    <go-select id="country" name="country"
      placeholder="Seleciona um país" required>
      <option value="pt">Portugal</option>
      <option value="es">Espanha</option>
      <option value="fr">França</option>
    </go-select>
  </go-field>
  <go-field label="Densidade">
    <go-radio-group name="density" value="comfortable">
      <option value="default">Padrão</option>
      <option value="comfortable">Confortável</option>
      <option value="compact">Compacto</option>
    </go-radio-group>
  </go-field>
  <go-checkbox name="terms" required>Aceito os termos</go-checkbox>
  <go-button type="submit">Submeter</go-button>
</form>

Mensagens de erro de validação

A validação de constraints é nativa: tenta submeter vazio e o navegador mostra a sua bolha de erro. Para uma mensagem persistente, usa o atributo error de <go-field> — é o equivalente direto ao <FormMessage /> do shadcn, mas sem schema.

Submeter 
{}
<go-field
  label="Palavra-passe"
  for="password"
  description="Mínimo 8 caracteres."
  error="Tem de ter pelo menos 8 caracteres."
>
  <go-input id="password" name="password" type="password"
    required minlength="8"></go-input>
</go-field>

Submit com FormData

No submit, a validação nativa já correu — só chegas ao handler com dados válidos. Lê tudo de uma vez com new FormData(form) e envia para o servidor (por fetch, por exemplo). Sem serialização manual.

Enviar-me uma cópia Enviar 
{}
const form = document.querySelector('form')

form.addEventListener('submit', async (e) => {
  e.preventDefault()
  // Constraints nativas já validadas pelo navegador.
  const data = new FormData(form)

  await fetch('/api/contact', { method: 'POST', body: data })
  // data.get('name') / data.get('message') / data.get('copy')
})
